整合代理維護對照。本輪只有美術線提交了新契約；後端與內容線尚未提供檔案。下面「現行」是 `main` @ `71f4d3c` 加上美術 M1 後，程式裡真正在用的介面。

## 戰鬥與科系

現場科系表是 `src/game/rpg/data.ts` 的 `DEPARTMENTS`。id 形如 `` `${discipline}-${college}-${index}` ``。土木工程學系是工學院第二筆，discipline 為 `engineering`。

`engineering` 的技能名稱是「結構脈衝」（傷害 40、範圍 12、冷卻 6）。`StructuralPulse` 讀 `attackFx`：範圍用 `attackFx.range`，命中對象用 `attackFx.hits`。其他學院的施放也讀 `attackFx`，各自畫 `CollegeCasts`。商管金幣只有一個命中點時，終點沿圓周散開，不疊在同一點。普攻光刃在 `src/game/art/vfx/basic-swing.ts`，跟著 0.46 秒攻擊片段從角色右側移到左側，蓄力幀在身前，長度約前臂，不跟著 `attackFx.range` 放大。

`char.student-kit` 的每個動作片段取 17 個時間點，比較背包正面的蒙皮頂點和同一高度的外套背面。揹帶仍綁在胸口，不計入這段間隙。最靠近的是 run，間隙 22.0 mm。背包骨轉 90 度會穿進外套 116.7 mm，測試會失敗。靜止姿勢的外套環檢查仍在。這不是第二套角色。

敵人 id 與種類（`src/game/rpg/data.ts`）：`quiz-1`…`quiz-4`、`report-1`、`report-2`、`exam-1`、`exam-2`、`final-1`。判定半徑仍是 `ENEMY_TYPES[kind].radius + 2.5`。預警圈用這個半徑。

委託面板的 `claim(id)` 只結 `MISSIONS`。同一個 `claimed` 陣列也收校園事件的 `quest-*` id。校園獎勵走 `grantQuestReward`，不另開背包。學期故事裡還有另一個同名函式，兩本帳沒有合併。

狀態卡可見文字來自 `BarReadout.short`（`src/game/rpg/status.ts`），形如「生命 62/108」。小數最多一位。長句 `line`（目前值、最大值、變化）只放在計量條的 `aria-label`。填色是生命 `#e09a8c`、專注 `#8eb8b4`、經驗 `#ddc691`，軌道 `#cfc6b0`，字色沿用 `--ad-ink`。提示畫在長條外面，窄卡用 `flex-wrap` 換行。窄於 700px 時 `.ad-target` 的 `top` 是 268px。快捷欄技能圖示讀 `SKILL_GLYPH`，一個學院一個 lucide 名稱，工程是 `DraftingCompass`。沒有第二份技能表。受擊邊緣是 `.ad-hurt` 的 `inset 0 0 72px 18px #b04c4799`。校園地圖的建物描邊讀 `zoneMark`，顏色來自既有清冊分區，圖例七個名稱是軸線、書圖、理工、教學、文藝、運動、生活。分區框會重疊，玩家所在區用 `zoneNear` 找最近的建物，不把框線當成實測界。展開的校園地圖在課程金圈上方寫兩個字：選系、移動、補給、普攻、技能。完成與沒有課程時不寫字。小地圖仍只畫金圈。

敘事預覽的 `quest-reward` 呼叫既有 `grantQuestReward`。非法效果（`set-hp`、`add-item`、`eval`、`script`、`mutate-save`）整段取消。預覽把結果寫在 `tk-narrative-preview-fixture-v1`。

校園進入點用同一條白名單。差額寫回主存檔的經驗、筆記、學分與 `claimed`。事件旗標、任務節點與已解決事件放在同一份存檔的 `narrative`，不是第二份生命或背包。內容套件的 `MAIN_INTEGRATION` 常數仍是 false。

## 存檔

兩把本地鍵，本輪都沒有改格式：

| 鍵 | 版本欄 | 內容 |
| --- | --- | --- |
| `tamkang-world-v1` | `version: 2`（`SAVE_VERSION`） | 巡禮造訪、光影、音量、畫質、舊背包與科系 |
| `tamkang-rpg-v2` | `snapshot().version === 2` | 生命、專注、任務 `claimed`、建築、背包槽、裝備 `loadout` 與 `gear`、位置、室內、收集進度 `gathered`、擊退紀錄 `felled`，以及同一份存檔上的 `narrative` 事件記憶 |

寫入是延遲 1.8 秒的本地 `localStorage`。另一個分頁寫入同一鍵時，`onForeignSave` 只把文字放進 `foreignText` 並把 `saveConflict` 設為 true，不直接覆蓋目前進度。玩家再選接受本機或接受外來。這是分頁衝突，不是雲端同步。

靜態建置不要求伺服器，也不含雲端面板、`/api/cloud` 或敘事預覽頁。雲端信封的 `contentVersion: 2` 是這份 RPG 存檔的 `version`，不是敘事 manifest 的 `revision: 1`。`?qa=1` 才掛上 `window.__rpgQA`，正式遊玩不讀它。

已登入的帳號可以列出自己最多 8 筆版本編號，並指定其中一筆寫回本機。列表不含存檔本體。版本不是 2、但帶有生命、經驗、背包、技能或已領任務的舊 RPG 檔是 `legacy_rpg`，雲端拒絕寫入，也不寫入巡禮表。巡禮檔仍是 `legacy_pilgrimage`。

RPG 快照裡的朝聖清單在寫入時拿掉空白、超過 64 字和重複的編號，只留前面 32 個。短編號如 `kenan` 留在最前面。沒有先存檔就直接送出超過 32 筆、或單筆超過 64 字的清單，雲端仍拒絕整份存檔。

多樣玩法的近況、已解和領取清單在匯入時拿掉空白筆記，也拿掉 80 字以上的筆記。79 字的有名字項目留下。沒有先匯入就直接送出空白筆記，雲端仍拒絕整份存檔。

進行中回合的失敗原因和回執超過 80 字會收到 80 字。學院名稱或學門超過 80 字改成沒有。事件編號超過 80 字的回合拿掉。訊號的事件編號須在 1 到 80 字，任務編號須是 1 到 64 個小寫英數、冒號、底線或連字號。叫不出名字的訊號拿掉。沒有先匯入就直接送出超過 80 字的失敗原因，雲端仍拒絕整份存檔。

敘事種子在匯入和寫入時，空白或達到 64 字就換成 `campus`。1 到 63 字的種子留下。亂數和記憶留著。沒有先匯入就直接送出空白或 64 字的種子，雲端仍拒絕整份存檔。

同一件獎勵先記在裝置上，再交給呼叫端的 `grant()`。登入只把回執抄到目前帳號。伺服器已記過就不再發。連不上伺服器時仍先發一次，回執留在該帳號佇列。帳號已經確認之後，再問一次登入如果失敗，仍先問伺服器這件獎勵記過沒有，已記過就不發。伺服器回應之後，記下或發放之前再對一次帳號。帳號換了或這次確認連不上，這件事維持未結，這個帳號可以再問。確認過且伺服器說已記過，仍不發。沒有第二套獎勵帳。

雲端讀寫先對 `/api/auth/get-session` 和這台裝置記的帳號。帳號不同就不上傳、不下載、不恢復、不發獎勵，原來的佇列留到該帳號回來。送出佇列時，每一筆之前再對一次目前登入的帳號。帳號已經換了，剩下的項目留在原帳號，不再送出。上傳成功的回應在記下版本之前再對一次帳號。帳號換了或這次確認連不上，這筆上傳留在原帳號佇列，不把那個版本記成這台裝置的寫入。接續上傳也一樣。收到 409 或 422 時，採用另一台裝置的存檔或丟掉這筆上傳之前，再對一次帳號。帳號換了或這次確認連不上，這筆上傳留在原帳號佇列，也不把另一個帳號的存檔拿來選擇。同一個帳號、另一台裝置的版本衝突仍會丟掉這筆並提供選擇。雲端讀到的存檔在寫入本機前再對一次帳號，所以不會把另一個帳號的存檔寫進來。

下載和指定版本恢復在寫入本機前，會先過白名單，再對內容校驗。未知欄位或校驗不符時，本機存檔維持原樣。指定版本恢復通過校驗之後，寫入本機前再對一次帳號。帳號換了或這次確認連不上，本機存檔維持原樣。指定版本恢復若收到版本衝突，在把那份存檔拿來選擇之前再對一次帳號。帳號換了就不提供選擇，確認連不上就維持本機。同一個帳號的衝突仍會提供選擇。連不上伺服器時，同一帳號的新上傳會取代佇列裡較早的那一份。同一佇列裡的獎勵回執留著。

下載、恢復上一份或指定版本寫入本機後，進行中的遊戲會暫停自動存檔，並用既有的存檔選擇問要保留現有進度，還是載入這份。存檔鍵仍是 `tamkang-rpg-v2`。生命值大於 0 時，載入會回到存檔裡的公共室內樓層。成功下載或恢復後，這個帳號尚未送出的存檔上傳會拿掉，獎勵回執留著。

送出佇列時只拿掉已經完成的項目。途中新排進來的獎勵回執留著。下載已經拿掉的上傳不會再送，也不會寫回帳號。如果那筆還是送到了，而且沒有更新的上傳在等，客戶端會把目前本機存檔寫回新的版本。已有更新的上傳則把那次版本當成自己的起點。離線上傳第一次送出時，用目前的本機存檔，請求編號不變。

失敗後再送時，改用最新的本機存檔和新的請求編號。直接上傳的回應若在離開瀏覽器後消失，這筆算已經送過一次，不記下版本。之後的本機進度用新的請求編號和較新的本機存檔。登入還在、資料庫回 503，或伺服器回 429、500 以上時，玩家已經要求送出的上傳留在這個帳號的佇列，算已經送過一次。存檔被拒時不排回佇列。登入逾期回 401，或工作階段沒有使用者時，這不算換成別的帳號。這個帳號已經要求送出的上傳和獎勵留在自己的佇列。直接寫入若回來是未登入，也排回這個帳號，請求編號沿用。已經排好的上傳若發現這個帳號的雲端列不在了，確認仍是這個帳號後，用新的請求編號把目前本機存檔做成第一次同步。另一個帳號的工作階段不會送出。同一個帳號、雲端仍有別的內容時，衝突仍會放下該筆。已登入時，獎勵回執若回 429，限流發生在寫入之前，這次先在本機發一次，回執留在這個帳號的佇列。422 不發獎，也不排進佇列。雲端仍是這台裝置上次寫入的那份時，新檔從那個版本接下去。雲端已是別的內容時，維持衝突，不覆蓋。那筆接續上傳若在送出途中被拿掉，客戶端會把玩家留下的本機存檔寫回，斷線也不再排回佇列。送出途中斷線時，已經被拿掉的上傳同樣保持拿掉。伺服器若已經收下同一份內容，客戶端會把玩家留下的本機存檔寫回。已有更新的上傳則把那次版本當成自己的起點。這次回寫再問登入時如果只是連不上，仍把玩家留下的本機存檔寫回。帳號已經換成別人時不寫，只記下看到的版本。已被拿掉的上傳若讀到同一份內容，在記下版本或寫回本機之前再對一次帳號。這時帳號換成別人，不記下那個版本，也不寫回。確認連不上時，仍把玩家留下的本機存檔寫回。地上掉落可以帶可選的 `quest` 標記。每個數量必須是整數，而且不能超過那一堆裡的同一物品。其他掉落欄位仍拒絕。
