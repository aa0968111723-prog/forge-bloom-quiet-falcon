# 狀態

第一條可玩的同步路徑已經接上真實 API 與資料庫，不是 mock。

訪客可以不登入，只寫瀏覽器的 `tamkang-rpg-v2`。登入後若雲端還沒有存檔，必須明示 `confirmFirstSync` 才會上傳。第二個登入的客戶端要再選下載，才會寫入自己的本機。兩邊用同一個 revision 寫入時，一個成功、一個收到 `revision_conflict` 與伺服器上的存檔。選擇保留本機會用伺服器回傳的 revision 再寫一次；選擇保留雲端只改本機。登出後本機存檔還在，未帶 session 的寫入是 401。

已驗證：

- 未登入、偽造 `userId`、另一個帳號都讀不到別人的存檔。
- 相同 `requestId` 重送不會增加 revision，也不會多插一筆獎勵回執。同一台裝置先離線領過的獎勵，登入、登出或換帳號都不會再發一次；回執只排進目前帳號。已登入時若伺服器說這個事件已經記過，這台裝置不會再發。確認 session 的那次連線中斷時，仍先問伺服器，不把已記過的事件在本機再發一次。
- 回執回應在記帳或發獎前會再確認 session。換成另一個帳號，或確認連不上，都不記這個事件、也不發獎，之後仍可再問。確認仍是這個帳號時，`applied: false` 不發獎，`applied: true` 才發一次。
- 舊巡禮 JSON 與目前的世界存檔被拒，`pilgrimage` 表維持 0 列。遊戲可匯入的舊版 RPG 不會被當成巡禮存檔，也不會上傳。雲端若回傳壞檔或校驗不符的存檔，下載和恢復都不會覆蓋本機。下載成功後，進行中的遊戲不會用自動存檔蓋掉這份。玩家改用這份且生命值大於 0 時，會回到存檔裡的室內樓層。
- 離線佇列只在原帳號登入後送出。同一個帳號只留最後一次上傳。成功改用雲端存檔或恢復舊版本後，這個帳號尚未送出的存檔上傳會拿掉，獎勵回執留著，另一個帳號的佇列不動。送出途中新排入的回執會留下；已經拿掉的上傳不會再送出。若那次上傳仍寫進了伺服器，而佇列沒有下一筆上傳，會把玩家留下的本機存檔再寫回去。第一次送出時若本機存檔比佇列裡的快照新，改送本機這份。送出失敗後若又繼續玩，重試改用新的請求編號送最新本機存檔；只有雲端仍是這台裝置剛才寫入的內容時，才接著寫上去。若這次續寫時玩家已經拿掉上傳，會把留下的本機存檔再寫回去。回應前斷線時，被拿掉的上傳不會重新送出；若雲端已經收下剛才那份，會再把留下的本機存檔寫回去。確認 session 的連線中斷時仍會寫回；session 已換成另一個帳號則不寫。瀏覽器 cookie 若是另一個帳號，佇列不會送出，也不會讀寫那個帳號的存檔。同一輪送出裡，前一筆完成後若 cookie 換成另一個帳號，後面的上傳會停住並留在原帳號。讀到雲端存檔後、寫進本機前若 session 已換人，本機進度不會被換成另一個帳號的存檔。
- 恢復指定版本的回應寫進本機前會再確認 session。換成另一個帳號，或確認連不上，本機存檔與尚未送出的上傳都保持原樣。
- 直接上傳若在回應前斷線，這筆算已經送出。內容沒變時仍用原來的請求編號重試。本機又有新進度就換新的請求編號；雲端若仍是剛才寫入的那份，就從那個版本接上。
- 玩家按下上傳時，若 session 仍有效但資料庫回 503，或寫入回 503、500、429，這次上傳留在原帳號佇列。資料庫恢復後再送出。內容被拒（422）不會排進去。
- session 過期回 401，或回應裡沒有使用者時，這台裝置仍記著的帳號會留下玩家按下的上傳與獎勵。獎勵先在本機發一次。重新登入後再送出。另一個帳號的 session 仍不會送出，也不發獎。寫入若回 401，上傳留在佇列。
- 已經排好的上傳若遇到空白雲端（`first_sync_required`），確認仍是這個帳號後，用新的請求編號把目前本機存檔做成第一次同步。另一個帳號的 session 不會寫進那份空白雲端。同一個帳號的版本衝突仍會放下該筆。
- 已登入時，獎勵回執若遇到 429，這次先在本機發一次，回執留在原帳號佇列。限流發生在寫入之前，所以之後仍可補記。另一個帳號的 session 不會送出這筆。422 不發獎，也不排進佇列。
- 存檔裡的朝向在寫入本機時折回同一圈。轉很久之後，面向與攻擊判定不變，整份存檔仍可上傳。雲端仍拒絕絕對值超過 100,000 的座標。
- 敘事地圖的值可以是 80 字，和內容記憶的上限一樣。寫滿一列仍可上傳，匯入後也留著。81 字仍會被拒，鍵仍須短於 80。
- 上傳或回執的回應標成完成前會再確認 session。換成另一個帳號，或確認連不上，都不記那個版本，該筆留在原帳號佇列。續寫自己剛才寫入的版本時也一樣。
- 版本衝突的回應先確認 session。換成另一個帳號，或確認連不上，都不把那個回應當成這個帳號的衝突，上傳留在原帳號佇列。確認仍是這個帳號時，別的裝置寫入的衝突仍會放下該筆。
- 恢復時的版本衝突也先確認 session。換成另一個帳號，或確認連不上，都不把另一個帳號的存檔拿來選擇，本機保持原樣。確認仍是這個帳號時，仍回傳這份雲端衝突。
- 斷線後若讀到的雲端就是剛才送出的那份，會再確認 session。已換成另一個帳號就不記那個版本，也不把本機存檔寫回去。確認連不上時仍會寫回。
- 刪除一個帳號的存檔頭、歷史、冪等請求與獎勵回執後，可以依備份列還原。另一個帳號的存檔不受影響。重開程序後同一筆存檔還在。
- `GET /api/health` 在資料庫連不上時仍是 200，`GET /api/ready` 是 503，`SIGTERM` 結束碼 0。
- 在 `53ec394` 上重跑：`tsc --noEmit` 通過，`npm test` 315 通過、0 失敗。
- 目前校園快照（48 座設施、敘事工作階段、多樣玩法盤面、掉落與位置）可以通過雲端驗證。掉落上的委託數量標記會留下，超過該堆數量或白名單以外的欄位會被拒。頂層 `score` 與敘事裡的額外欄位會被拒。
- `npm run build:site` 通過，`dist` 不含 `cloud-save` 或 `DATABASE_URL`。
- 已併入室內續玩的 `main`（`42b5e59`）。圖書館 3 樓的校園存檔經客戶端首次同步、第二個客戶端下載，並在程序重開後仍讀得到 `interiorId`、`floor`、敘事與多樣玩法。
- 「上傳本機」會先看雲端：沒有存檔才做首次同步，已有版本則用該 revision 續寫，衝突時不覆寫。離線上傳留在原帳號佇列，換帳號不會送出。資料庫回 503、500 或 429 時也留在佇列；422 不會排進去。重新載入或回到該帳號登入後才送，相同 requestId 不會增加 revision。
- 已併入圖書館坡道欄杆（`70cf72c`）。程序重開後，同一個首次同步請求會重放且 revision 仍是 1；改內容重送同一 requestId 會被拒，樓層與經驗值不被改掉。
- 玩家可以恢復上一份雲端版本。它會變成新的 revision，並寫回本機；只有一份版本時本機不變。
- 玩家可以列出自己最多 8 筆雲端版本編號，並指定其中一筆寫回本機。列表不含存檔本體，其他帳號看不到。超過 8 筆的舊版本會被刪掉；恢復已刪版本不會改本機，也不會記獎勵。
- 建成補給站的冷卻（`facility:` 加建築 id）在匯入與雲端重載後仍在，重寫的本機存檔仍通過雲端驗證。已過期或超過 180 秒的時間不會留下。
- 匯入時遊戲留在隔離區的未知物品與裝備可以上傳。背包與正在穿戴的裝備仍用既有 id 格式。超過 64 字的隔離 id 不會留下，也不會通過雲端驗證。
- 目前 36 個野外補給點加上 48 座建成設施的冷卻可以一起通過雲端驗證，建築 id 可以到 80 字。超過 112 個採集鍵，或設施 id 超過 80 字，整份存檔會被拒。
- 多樣玩法進行中時，能力快照的 `built` 用累計放置次數。同時站著的設施仍最多 48 座，但拆掉再蓋後這個次數可以超過 48。雲端接受到與頂層 `built` 相同的 10,000,000；再高會拒。匯入時也保留這個次數，不會把它壓回 48。

沒有合併 `main`，沒有部署。

收集委託的 `gathered` 與 `felled` 已在同一份白名單，並跟圖書館樓層一起經過上傳、下載與程序重開。地面掉落的委託數量標記也在程序重開後留著，內容雜湊仍和讀回的文件一致；恢復重開前的第一個版本時，委託標記還在，收集計數回到該版本。建成補給站仍在冷卻時間內時，匯入或改用雲端存檔不會把冷卻清掉，玩家不能立刻再領一次冰咖啡。沒有這些欄位的舊存檔仍可上傳。程序重開後，收集計數、已領委託與版本列表還在；同一個收集回執用新的 requestId 重送不會再次記帳。舊版 RPG 匯入檔仍是 `legacy_rpg`，不會寫進巡禮表。下一步：內容或玩法若再新增 `snapshot()` 欄位，先補 `src/features/cloud-save/contract.ts` 的白名單再讓存檔上傳。不要在同步路徑執行內容檔。
