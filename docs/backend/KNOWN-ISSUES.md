# 已知限制

- 信箱密碼預設關閉。玩家要使用本機註冊時，程序需有 `AUTH_EMAIL_PASSWORD=true`。`scripts/game-services-server.mjs` 只在非正式環境自動打開。Grok OAuth 仍走原來的 Better Auth 設定。
- 正式環境的 `scripts/game-services-server.mjs` 沒有 `BETTER_AUTH_SECRET` 會直接結束。開發用密鑰寫在 gitignore 的 `data/dev-auth-secret`，不會印到 log。
- Better Auth 的 `session_data` cookie 最多可在 300 秒內不查資料庫。整合測試會拿掉這顆 cookie，再把 `session.expiresAt` 設成過去，確認只靠 session token 時過期會 `401`。
- 限流計數在程序記憶體，多實例不會合併。另外，正式環境的 Better Auth 對 `/sign-in` 與 `/sign-up` 另有每 10 秒 3 次的限制；那是登入套件的行為，不是存檔 API。
- 遊戲讀回敘事時會把 `activeEventId` 清成空、模式改回探索。雲端仍保存玩家上傳時的進行中事件，另一台載入後會依遊戲既有規則結束該事件。這不是用裝置時間決定覆蓋。
- 多樣玩法盤面接受已知 `board` 類型裡的巢狀資料，但沒有逐欄複製內容代理的盤面 schema。新的盤面類型要先加進白名單。
- 沒有競技排行榜，也沒有公開的管理、發獎或列出所有玩家的端點。存檔裡的經驗與貨幣不是伺服器結算的分數。
- session 過期回 401，或回應裡沒有使用者，會當成這台裝置暫時送不出去，上傳與獎勵留在原帳號。另一個帳號的 session 仍是換人。每一筆雲端讀寫前都會再確認 session。確認用的那次回應若在解析時 cookie 又換人，這一次請求仍可能帶著新 cookie 送出；同一輪後面的項目不會再送。恢復請求若已帶著另一個帳號送出，那個帳號的雲端版本可能已被複製；這台裝置不會把該回應寫進本機。確認連不上時，恢復回應同樣不寫進本機。上傳、回執或續寫若已帶著另一個帳號送出，那個帳號的雲端可能已寫入；這台裝置不把該版本記成原帳號的進度，該筆留在原帳號佇列。確認連不上時同樣不記版本、不標成完成。版本衝突的回應若無法確認仍是這個帳號，也不放下該筆、不把另一個帳號的存檔拿來選擇。確認仍是這個帳號時，別的裝置造成的衝突仍會放下該筆。恢復時的版本衝突若無法確認仍是這個帳號，也不拿來選擇、不改本機。
- 已經排好的上傳若發現這個帳號的雲端列不在了，會改以首次同步寫入目前本機存檔。確認不是這個帳號時不寫。同一個帳號、雲端仍有另一份內容時，衝突仍會放下該筆。
- 遊戲存檔時把朝向折回同一圈，長時間轉視角仍可上傳，面向不變。手改成絕對值超過 100,000 的座標仍會被拒。
- 敘事地圖的值最多 80 字，和內容記憶相同，匯入會留下。81 字仍會被拒。鍵仍須短於 80。
- 存檔會把敘事亂數折成 32 位元無號整數，並把敘事分鐘收到 0 到 1,000,000。沒有先存檔就直接送出超出範圍的亂數或分鐘，雲端仍會拒絕整份存檔。
- 存檔會把空的或超過 63 字的敘事種子改成 `campus`。沒有先存檔就直接送出這種種子，雲端仍會拒絕整份存檔。
- 存檔會拿掉不符合雲端 id 格式的敘事地點，以及超過 80 字的敘事科系。沒有先存檔就直接送出這些值，雲端仍會拒絕整份存檔。
- 存檔會把敘事冷卻與互斥時間收到 -1e12 到 1e15。沒有先存檔就直接送出超出範圍的時間，雲端仍會拒絕整份存檔。
- 存檔會拿掉敘事地圖的空鍵，以及事件清單裡的空字串。沒有先存檔就直接送出這些空值，雲端仍會拒絕整份存檔。
- 匯入會拿掉多樣玩法近況、已解事件與委託紀錄裡的空字串。沒有先匯入就直接送出空字串，雲端仍會拒絕整份存檔。80 字的紀錄同樣會在匯入時拿掉。
- 匯入會把多樣玩法的失敗原因與回執收到 80 字，並拿掉無法命名的進行中事件、過長的學院或學科 id，以及任務 id 不合格式的訊號。沒有先匯入就直接送出這些值，雲端仍會拒絕整份存檔。
- 存檔會拿掉超過 64 字的已領取委託 id。沒有先存檔就直接送出這種 id，雲端仍會拒絕整份存檔。
- RPG 存檔最多寫入 32 個不重複、而且不超過 64 字的巡禮地標。沒有先存檔就直接送出更長的清單或 id，雲端仍會拒絕整份存檔。本機巡禮清單本身不因此改短。
- 匯入會把超過 80 字的掉落 id 收成前 80 字，空 id 換成新的 id，並把絕對值超過 100,000 的座標收到可走範圍內。物品與委託標記留著。沒有先匯入就直接送出這些值，雲端仍會拒絕整份存檔。
- 移動教學的錨點若超出雲端座標範圍，匯入與讀回會當成沒有錨點，匯入時改站在玩家腳下。沒有先匯入就直接送出超出範圍的錨點，雲端仍會拒絕整份存檔。
- 存檔與匯入只留下校園清單裡的發現地點。沒有先存檔就直接送出清單以外的發現文字，雲端仍會拒絕整份存檔。
- 匯入會把隔離裝備的耐久收到 0 到 100,000。沒有先匯入就直接送出超出範圍的耐久，雲端仍會拒絕整份存檔。
- 存檔會拿掉已過期或建築 id 不允許的採集冷卻。冷卻還沒結束的設施鍵，即使建築已經拆除，仍會留下。沒有先存檔就直接送出超過 112 個鍵，或不合格式的鍵，雲端仍會拒絕整份存檔。進行中的這一局仍用記憶裡的冷卻，要等下次讀檔才改成存檔留下的那一份。
- 隔離清單滿 24 筆時，匯入不再把認不得的背包物品併進去，存檔也只留先到的 24 筆。沒有先存檔就直接送出超過 24 筆的隔離物品，雲端仍會拒絕整份存檔。進行中的這一局若記憶裡已超過 24 筆，要等下次讀檔才改成存檔留下的那一份。
- 存檔會把超過 16 種物品的地面掉落拆成多堆。地面已經有 100 堆時，會先併兩堆能合在一起的掉落，再把多出來的種類留在原來的位置。沒有可以合併的堆時，多出來的種類仍不會寫進這 100 堆。沒有先存檔就直接送出超過 16 種的掉落，雲端仍會拒絕整份存檔。進行中的這一局若記憶裡的一堆已超過 16 種，要等下次讀檔才改成拆開的那幾堆。新的掉落不會再把第 17 種塞進同一堆。
- 地面已滿 100 堆、腳邊也沒有可併的空位時，多出來的物品仍放不下去。這和原本的掉落上限相同。沒有先存檔就直接送出超過 100 堆的掉落，雲端仍會拒絕整份存檔。
- 離線佇列重試時，內容沒變才沿用原來的 request id。本機又有新進度就換新的 request id。同一個 requestId 若已在伺服器對上不同內容，重試改用新的 request id。雲端仍是這台裝置剛才那份時，從該版本接上本機新進度。雲端已是別的內容則放下該筆，不覆蓋，本機存檔留著。直接上傳若在回應前斷線，也算已經送出，新進度不會沿用那次的 request id。直接上傳若收到 503、500、429 或 401，也算已經送出。續寫自己剛才那份，或空白雲端的第一次同步，若回 401，也算已經送出。續寫若回 500 或 429，留在佇列，不放下。422 不會排進佇列。雲端若已是另一份內容，重試不會覆蓋。玩家在續寫途中拿掉上傳時，會把留下的本機存檔再寫回去。回應前斷線時，被拿掉的上傳不會重新送出；確認 session 的連線中斷時仍會寫回；session 已換成另一個帳號則不寫。斷線後讀到的雲端若屬於另一個帳號，也不記那個版本、不把本機存檔寫回去。若事後讀不到雲端，下次檢查才看得到差異。
- 獎勵回執只保證不重複記帳。客戶端若在回執成功之後當掉、又還沒執行本機發獎，重試不會再發。回執回應若無法確認仍是這個帳號，這一次不記帳也不發獎，之後仍可再問。若該請求已帶著另一個帳號送出，那個帳號的回執可能已寫入；這台裝置不把它當成這個帳號的結果。限流回 429 時寫入還沒發生，這次會在本機發一次並把回執留在原帳號；422 不發獎。既有 `grantQuestReward` 仍以任務 id 自己防重。
- 內容效果白名單檢查結構，不執行內容檔。穩定的任務、物品、技能 id 仍由內容資料定義；這份 API 不另造一套 id。
- 開發庫是檔案型 PGLite（`PGLITE_DATA_DIR`）或記憶體 PGLite。正式庫是 `DATABASE_URL` 指向的 PostgreSQL，由 `scripts/migrate.mjs` 套用同一批 SQL。沒有破壞性遷移。
- 直接用 Node 載入這些 TypeScript 檔需要 `--experimental-transform-types`，因為既有 `pglite-dialect.ts` 使用 parameter property。`npm test` 裡的整合測試會自己帶這個旗標。Vite / `tsc` 不需要。
- 靜態站不會呼叫這些 API。雲端同步只存在於有登入 session 的 Node 程序。
